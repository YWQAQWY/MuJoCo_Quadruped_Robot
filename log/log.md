# PPO 四足机器人修改记录

## 2026-08-17：第二阶段前进训练修复

### 根因

- `stage2_forward_gait/last.pt` 实际前进速度只有约 `0.001–0.002 m/s`，足端接触率接近 100%，策略收敛为稳定站立。
- 原二值步态奖励使四脚着地仍获得一半匹配奖励；`vx=0.2 m/s` 也可能被静止策略按绝对误差阈值误判成功。
- `contact_force_threshold` 原先未被使用，课程难度只随 iteration 增长，新增相位输入不足以让继承的站立策略主动抬脚。

### 实现

- 增加参数化对角小跑参考轨迹和残差控制：`q_target = q_default + q_reference + action_scale × residual_scale × action_ppo`。静止指令下 `q_reference=0`。
- 使用 MuJoCo 法向接触力、进入/释放双阈值和足端/腿部/躯干分类；评估信息新增足端接触率、腾空率、对角接触率和机身接触次数。
- 将步态匹配改为平滑相位约束：摆动腿触地、支撑腿失联、摆动脚高度不足和高速落脚均为代价。四脚全部着地不再获得正步态奖励。
- 第二阶段改为能力驱动课程，连续两次满足门槛才提升指令范围、残差比例和随机化强度；初期关闭随机推搡和动力学随机化。
- 评估增加方向、最低速度比例和静止漂移条件。前进指令要求实际速度至少达到目标的 60%，因此静止策略不能通过 `0.2 m/s`。
- checkpoint 增加课程状态，并继续保存完整配置；回放程序从 checkpoint 恢复环境配置，确保参考步态和残差控制不会在键盘回放时丢失。
- 新增 `scripts/validate_reference_gait.py`。训练入口会核对当前参考参数是否存在于合格扫描报告，未通过时拒绝开始第二阶段训练。

### 参考步态验证结果

- 扫描 384 组参数，28 组通过全部硬门槛。
- 当前默认组：频率 `1.8 Hz`、占空比 `0.52`、髋摆幅 `-0.15 rad`、膝周期摆幅 `-0.1 rad`、摆动屈膝偏置 `+0.45 rad`、相位偏置 `-0.8 rad`。
- 10 秒无摔倒，平均前进速度 `0.615 m/s`，单脚腾空率约 `42%–47%`，四脚同时着地率 `1.2%`，躯干接触为 0。
- 完整报告：`logs/reference_gait_scan.json`。

### 使用命令

```bash
# 1. 修改参考参数后必须重新扫描
.venv/bin/python scripts/validate_reference_gait.py

# 2. 从第一阶段合格站立模型开始第二阶段
.venv/bin/python scripts/train_ppo.py --stage stage2_forward \
  --init-checkpoint runs/locomotion_v2/best.pt --run-name stage2_forward_residual

# 3. 中断后恢复（课程等级也会恢复）
.venv/bin/python scripts/train_ppo.py --resume runs/stage2_forward_residual/last.pt

# 4. 仅在生成 best.pt 后进行键盘回放
.venv/bin/python scripts/play_ppo.py \
  --checkpoint runs/stage2_forward_residual/best.pt --keyboard
```

## 2026-08-17：DogML 机器人形态调研

- DogML 来自 T2QRM（ACM Multimedia Asia 2024），包含配对的狗和四足机器人运动及文本描述，目标是文本生成和运动模仿，不是直接发布的低层 state-action 控制数据。
- 官方 T2QRM 仓库截至本次检查仍标注控制代码尚未发布，数据包也不包含机器人 URDF、质量、惯量、关节轴、力矩限制和执行器参数，因此无法确认具体机器人型号或完整动力学。
- 从200段 walk/trot 的固定骨长统计得到：髋外展连接约0.056 m、上腿约0.2531 m、下腿约0.2510 m；当前模型上/下腿均为0.2 m，且髋外展与髋俯仰关节共点，没有独立侧向髋连杆。
- 两者都是四腿、每腿三旋转关节的12-DOF拓扑，但几何尺度和髋结构不同；这解释了简单关键点逆运动学在当前模型上复演失败。
- 未修改主 `quadruped.xml`：直接改变连杆长度和髋结构会使现有站立模型、参考步态、PD参数及全部checkpoint失效，而且缺失的DogML惯性/执行器数据仍只能猜测。
- 决策：当前基础行走继续使用已验证模型；DogML模仿应在获得官方URDF/代码后建立独立模型分支，再进行动力学重定向，不能覆盖现有训练环境。

## 2026-08-18：修复前进过程中持续转弯

- `stage2_faster_walk` 后期在 `0.5 m/s` 下净航向漂移达到 `-0.070 rad/s`，10秒累计约-0.7 rad；原0.2 rad/s阈值过宽，使明显弧线仍被判成功。

- 新增横向速度平方惩罚 `lateral_velocity=-1.0`，减少策略通过侧滑和左右不对称提高前进速度。

## 2026-08-19：修复评估/回放残差放大 10 倍的 bug

- 根因：训练时 level 0 残差尺度为 0.02，但 `evaluate()` 和 `play_ppo` 建环境时未设置课程尺度，使用了 `residual_control.scale=0.2` 默认值，策略残差被放大 10 倍执行。
- 症状：站立时策略输出被放大成 100° 深蹲（v5 实测关节偏差 1.75 rad）、评估漂移 -0.17 rad/s、前进"刹车+偏移"——v2~v5 的评估数字全是放大后的假象。
- 修复：评估环境使用当前课程等级的残差尺度；checkpoint 新增 `curriculum_residual_scale`；回放恢复该值（旧 checkpoint 从课程等级推导）。
- 修复后实测 v5 模型：站立偏差 12°，0.2→0.262 m/s 漂移 -0.011，0.3→0.318 m/s 漂移 +0.004，模型本身一直正常。

## 2026-08-19：漂移惩罚与观测重构

- `speed_shortfall`（只罚欠速）改为对称 `speed_error=-2.0`（|cmd−vx|），防止策略学出统一提速偏置；`straight_heading` 提高到 -5.0。
- 累计航向惩罚随时间平方增长，在 γ=0.99 折扣下被"后置折扣"掉，策略无视漂移；瞬时 ωz² 惩罚又会误伤步态振荡（RMS≈0.4）。
- 新增低通滤波偏航率 EMA（τ≈1s，`yaw_drift_alpha=0.02`）：只保留持续漂移、滤掉 1.8 Hz 振荡，惩罚即时生效；EMA 加入观测。
- 航向误差 sin/cos 与 EMA 进入观测，54→57 维；actor/critic 可直接看到漂移，`straight_heading` 与 `yaw_drift` 才真正可优化。
- `yaw_drift` 由平方改为线性 `-5.0×|ema|`，小漂移（0.017 rad/s 级别）也有梯度。
- 回放兼容：45/48/54 维旧 checkpoint 保留；56 维（v4）废弃；48→57 输入扩展复用原机制。
